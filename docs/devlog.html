コラージュ ドラッグ移動・リサイズ実装 ＋ アプリ連携設計

UI設計

実装・変更

  • コラージュ画像のドラッグ移動を実装（管理モード限定）
  • 右下コーナーハンドルによるリサイズを実装（管理モード限定）
  • 位置・サイズを localStorage に保存、リロード後も維持
  • タッチ操作（スマホ）にも対応（touchstart / touchmove / touchend）
  • GitHub にコミット・プッシュ済み（commit: 2ea3463）

設計検討：アプリ連携（MiteOrder → EasyReply → SchedulEX → RakuThrough）

  • SchedulEXのFirestore構造を確認：/users/{uid}/schedulex/data に orders 配列を1ドキュメントで管理
  • 連携用に /requests/{id} コレクションを新設してHubとする方針に決定
  • 既存の schedulex/data は直接触らない（外部書き込みによるデータ破損防止）
  • SchedulEXの設定メニューに「EasyReply連携」項目がすでに存在（未実装）→ 連携想定済みの設計
  • RakuThroughはSchedulEXとは別Firebaseプロジェクト → multi-project SDK で書き込む

検討してやめたこと

  • SchedulEXのFirestoreを直接Hubにする案 → orders が1ドキュメント配列のため外部同時書き込みでデータ破損リスクあり、却下
  • RakuThroughを依頼カードのマスターにする案 → 帳簿アプリが受付管理を持つのは役割過多、却下
  • MiteOrder + 外部DB（Airtable等）でマスター管理 → サービス追加コストと複雑さで却下
  • コラージュのドラッグを常時有効にする案 → 訪問者が誤って崩せるため管理モード限定に

残タスク

  • RakuThroughのFirestoreコレクション構成を確認
  • /requests コレクションのフィールド設計を確定
  • MiteOrderのフォーム送信 → Firestore書き込みの実装
  • EasyReplyへの依頼カードUI追加
  • SchedulEX側：accepted requests の取り込みUI追加
